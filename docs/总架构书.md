## 12. 分发：绿色免安装包（2026-09-28 作者要求"给别人的一键部署"）

**目标**：把 Python 运行时 + ComfyUI 引擎 + 模型 + 应用全部打进一个文件夹，拷到新电脑双击即用，**完全离线**。

### 布局（`E:\Qwen21Portable\`，可整体改名/搬盘）
```
一键启动.bat            # 双击入口：自检显卡 → 写配置 → 起后端（后端自己拉 ComfyUI）→ 开浏览器
环境自检.bat            # 显卡/驱动/磁盘/文件完整性/运行时 体检
使用说明.txt            # 用户文档（含 18+ 与法律声明）
config.json             # 由启动器按当前路径**自动生成**（所以搬到哪都能用）
runtime\                # python-build-standalone 3.13 + 合并进来的 site-packages(torch cu130 等) ≈6.4GB
ComfyUI\                # 引擎核心 + custom_nodes\ComfyUI-GGUF + models\ ≈15GB
app\                    # bootstrap.py（自检+写配置+起服务）/ check_env.py / src\backend / web
output\                 # 出图
```

### 关键设计（为什么这样能"绿色"）
1. **运行时可用性靠"基础解释器 + 直接灌 site-packages"**：不用 venv（venv 的 `pyvenv.cfg` 会把绝对路径钉死）。把 pbs 基础 Python 与 ComfyUI 的 site-packages 合并成一个普通解释器树，包内 DLL（torch/lib 内自带 CUDA 库）都是相对路径 → 整包可搬。
2. **路径全部由启动器推导**：`bootstrap.py` 用自身位置算 ROOT，每次启动重写 `config.json`，因此**目标机路径任意**（不会出现"装到别的盘就不认"）。
3. **低显存自动降配**（作者要求；本包只支持 N 卡）：`bootstrap` 读 `nvidia-smi` → <12GB 时优先切 `qwen-image-2.1-UC-Q4_0.gguf`（本包附带），并给 ComfyUI 加 `--lowvram`；配置项 `comfy_extra_args`。
4. **服务自愈**：应用启动时若探测到 ComfyUI 不在线会自动拉起（`service.py`），并把日志写到包内。

## 14. 桌面版外壳（v0.4，2026-09-28 作者要求「界面变成 desktop」）

**目标**：双击一个 exe → **原生窗口**（无浏览器标签、无地址栏），后端与引擎不变。

**形态**：Electron 外壳（v40.10.2，取本机 `%LOCALAPPDATA%\electron\Cache` 里的纯净 zip，不翻墙），置于包内 `desktop\`（便携布局：`Qwen-Image-2.1.exe` + dll + `resources\app\`）。

**启动链**
```
desktop\Qwen-Image-2.1.exe
 ① 先探测 127.0.0.1:8777 —— 已有后端就直接连（绝不重复拉起 → 避免幽灵双实例分流请求）
 ② 否则 spawn runtime\python.exe app\bootstrap.py（带 QWEN21_NO_BROWSER=1，并清 PYTHONPATH/PYTHONHOME）
 ③ 轮询 /api/status 就绪 → 开 BrowserWindow 载入 http://127.0.0.1:8777
 ④ 窗口关闭 → 只杀「自己启动的」子进程（预先存在的后端不动）
```

**便携性**：ROOT 由 exe 位置推导（`dirname(execPath)/..`），整包可改名/搬盘；`userData` 重定向到 `<ROOT>\data\desktop`，**不污染目标机 %APPDATA%**。

| 实现点 | 做法 |
|---|---|
| 菜单栏 | `Menu.setApplicationMenu(null)` + `autoHideMenuBar` + `setMenuBarVisibility(false)`（技能规则 7） |
| 快捷键 | 菜单没了要自己兜：`before-input-event` 处理 F5 / Ctrl+R / F11 / F12 |
| 外链 | `setWindowOpenHandler` → 交系统浏览器，不在窗口内跳走 |
| 失败即退 | 起不来/载入失败/超时 → 原生错误框 + `app.exit(1)`，**不留僵尸进程占 userData 缓存**（技能规则 13） |
| 单实例 | `app.requestSingleInstanceLock()`，第二次双击只聚焦已有窗口 |
| 自检 | `--smoke`：等 DOM 出现 `#genChar` 且无结果面板残留 → `capturePage` 截图 + 写 `smoke-result.json` 后退出（技能规则 4/5） |

**不做**：安装器（保持绿色免安装）；不额外内嵌第二份浏览器内核（直接用 Electron 自带 Chromium，无需目标机装 WebView2）。

## 14.1 启动进度反馈（v0.5.7，作者：「启动时没有进度条」）

**问题**：桌面版启动要 18~20 秒（要拉起 ComfyUI 引擎），期间只有一个静态提示窗，**看着像卡死**。

**做法**：启动画面升级为**带真实进度的 splash**，阶段由后端日志驱动（不是假动画）：

| 阶段 | 触发（bootstrap 输出） | 进度上限 |
|---|---|---|
| ① 检测显卡与运行环境 | `[自检] 显卡: …` | 22% |
| ② 启动 AI 引擎（ComfyUI） | `[app] ComfyUI 未运行，尝试拉起…` | 64% |
| ③ AI 引擎就绪 | `[app] 服务已启动（v0.37.4，14s）` | 80% |
| ④ 启动本地服务 | `[app] Qwen-Image-2.1 应用已启动…` | 94% |
| ⑤ 界面加载中 | `/api/status` 首次返回 200 | 100% |

- 每个阶段上限内**按时间平滑推进**（600ms tick），所以不会"一格一格跳"也不会假装跑满；
- 另显示**百分比 + 已用秒数 + 当前提示**；
- 6 秒仍解析不到日志时的兜底：按时间推进到 ②（防止后端措辞变更导致进度条卡住）。

**实测坑（重要）**：子进程 Python 的 stdout 有两个坑，都直接毁掉进度条：
1. **块缓冲**：输出到管道要攒够约 8KB 才吐 → 阶段日志晚到，进度条停在「正在初始化」（4s/12s 取证截图均停在初始态）→ 修：spawn 加 `PYTHONUNBUFFERED=1`。
2. **编码**：Python 按 console/locale 用 **GBK** 输出中文 → 日志乱码，且**阶段关键词匹配全失败**（`.bat` 启动时必现，实测桌面日志出现 `Qwen-Image-2.1 ����Ӧ��`）→ 修：spawn 加 `PYTHONIOENCODING=utf-8`。
修复后实测：4s → ② 29%、12s → ② 44%（含"已用 12s"）。

**取证**：`--splashshot` 在启动第 4s / 12s 各截一张 splash 图后自动退出。

### 15.1 自适应（v0.5.1，作者：「ui比例不能自适应」）

**问题**：卡片写死 `max-width:760px` + 页面用普通流式块 → 窗口最大化后内容挤在左侧、右侧大片空白；窄窗口又会挤压不换行。

**规则（实现即以此为准）**

| 层 | 做法 |
|---|---|
| 页面容器 | `#main` 用 `padding: clamp(16px,1.4vw,30px) …`，不再限制总宽 |
| 卡片排布 | `.page` 改为 **CSS Grid**：`repeat(auto-fit, minmax(min(100%,382px),1fr))` → 宽屏多列、窄屏自动单列；`h2/.hint/#jobList/#gallery` 用 `grid-column:1/-1` 独占整行 |
| 卡片 | 去掉固定 `max-width`，改 `max-width:min(100%,880px)` + `min-width:0` |
| 字段网格 | `.grid3/.grid4` 改 `repeat(auto-fit,minmax(130~150px,1fr))`；`.row` 允许 `flex-wrap` |
| 字号/内距 | 关键尺寸用 `clamp()` 随视口缩放（标题 `clamp(19px,1.1vw,24px)`、卡片内距 `clamp(13px,.9vw,18px)`） |
| 侧栏 | `width:clamp(196px,15vw,248px)`；`≤980px` 折叠成 72px 图标条（隐藏文字与状态卡文字） |
| 窗口下限 | 允许缩到 720×600（否则看不到折叠效果） |

**验收（量化）**：在 900 / 1280 / 1920 三种宽度下，自检记录 `行内卡片数`、`主按钮是否在首屏`、`是否出现横向滚动`、`侧栏宽度`；要求：1920 时一行 ≥2 张卡片、900 时无横向溢出且侧栏折叠、三种宽度下主按钮均可见。

### 15.3 预设选择器改为「下拉内管理」（v0.5.4，作者：「删除直接在下拉列表时能删除就行了，为什么要新弄一个删除按钮」）

**问题**：原来每个预设是「原生 select + ＋ + 编辑 + 删除」四个控件并排，既有冗余按钮、破坏表单节奏，也让删除动作与它作用的对象分离（要先在下拉里选中、再去点旁边的删除）。

**改法**：自研组合框 `.combo`（原生 select 退居为隐藏的状态持有者，保证 `compose()` / 自检断言不变）

| 交互 | 行为 |
|---|---|
| 点击字段 | 展开列表（玻璃面板，定位在字段下方，最高 280px 可滚） |
| 列表行 | 预设名 + 当前项打勾高亮；**悬停显现「✎ 编辑」「✕ 删除」** |
| 行内删除 | 直接删该行（仅二次确认），删空自动补一条空白项 |
| 列表底部 | 「＋ 新增人物/画风预设…」固定一行 |
| 关闭 | 点外部 / Esc / 选中后自动关 |

**连带清理（砍冗余）**：删除 6 个按钮（`#charAdd/#charEdit/#charDel/#styleAdd/#styleEdit/#styleDel`）及其绑定与 `.pick` 相关样式；`--smoke` 的预设断言改为「组合框存在 + 列表行带删除入口 + 有新增行」，`--uiaudit` 增加展开列表截图。

**打磨（视觉审查后）**：① 行内操作图标**常显 45% 透明度**（不再是 hover 才出现，提高可发现性）② 编辑/删除间距加到 7px 防误触（删除另有二次确认）③ **「（空白）」占位项不给编辑/删除入口**。

### 15.4 布局定稿：内容顶部对齐（v0.5.5，作者：「还不如置顶呢」）

**过程**：作者只说了「窗口空白部分太大」→ 小悠先补横向（卡片按行均分撑满，390→525，消掉右侧约 410px 空带）→ 又把内容垂直居中（空白上下平分）→ 作者指出「还不如置顶」。
**结论（定稿）**：**页面内容一律顶部对齐**（`align-content:flex-start`），留白集中在下方，符合工具类应用的阅读动线；不再做垂直居中。

| 项 | 定稿 |
|---|---|
| 横向 | 卡片 `flex:1 1 330px` 按行均分撑满；单卡片页（编辑/抠图）居中 |
| 纵向 | **顶部对齐**；卡片在同一行内等高（`align-items:stretch`）；**卡片内控件同样置顶**（v0.5.6：移除「角色与画风」里用于分配空隙的 `.grow`，空白留在卡片底部）；例外：`#genPrompt/#editPrompt` 保留 `flex:1` 撑满卡片（写长提示词更舒服，属有意设计） |
| 默认窗口 | **1440×910 舒适窗口**（不强制最大化；仅当屏幕工作区高度 <820px 才最大化） |
| 度量标准 | 审计/自检**按舒适窗口尺寸**测量，不再拿最大化窗口当基准（作者：「事实上不一定要最大化窗口测试」） |

**验收（舒适窗口 1440×910）**：内容底部留白 95~300px（此前最大化下为 480~707px）；三卡等宽等高、横向无空带。
